# QQ Bridge 二代仿真设定（default）

> 目标：让 AI 像一个"有自己的生活、偶尔看看群、被叫必回、有话题就接、没话题就安静"的真人，
> 而不是 24 小时在线的客服机器人。
>
> 生效位置：`qq-bridge/config.json` → `socialV2` 字段（控制台热更新，无需重启 bridge）。

## 六、设计思路

1. **不刷存在感**：普通消息只 8% 概率接话，潜水是默认状态，被点名必回。
2. **真人打字感**：条间 1.2~4 秒，25% 概率停顿 8~20 秒，模拟思考/忙别的事。
3. **不抢话**：收到新消息后至少等 12 秒，判断对方说没说完。
4. **适度主动**：群冷场 20 分钟后，每 45分钟~2小时 有一次 25% 概率的主动开口机会。
5. **记忆与黑话**：轻量记忆 + 黑话学习，让 AI 记得人、接得住梗。

## 七、修改方法

### 方式一：控制台 API 热更新（推荐，无需重启）

```bash
# 编辑 state/socialv2-recommended.json 后执行：
node scripts/apply-socialv2-config.mjs
```

### 方式二：控制台网页

1. 浏览器打开 `http://127.0.0.1:3100`
2. 输入令牌：`061228-bridge-console`
3. 进入二代仿真配置页面修改

### 方式三：直接改 config.json

修改 `qq-bridge/config.json` 的 `socialV2` 字段，然后重启 bridge（`start.bat`）。

## 六、错误拦截（429 限流保护）

当 DSH 使用的模型（如 DeepSeek Free / opencode Zen）触发限流（429）时，bridge 不会把原始报错发到 QQ，而是：

1. **拦截错误**：检测 `429`、`rate limit`、`FreeUsageLimitError`、`quota exceeded` 等关键词
2. **发送友好提示**：`🐟 小鲸鱼饿了，需要主人喂饭～`
3. **自动退出**：等待 2 秒让消息发出去后 `process.exit(1)` 结束 bridge 进程
4. **避免反复报错**：不会用其他付费 token 继续消耗

用户只需重启 bridge（`start.bat`）即可恢复。无需手动排查报错。
