# QQ Bridge 安装配置经验总结

> 环境：Windows 11，DSH 桌面端，NapCat
> 日期：2026-08-28
> 目标：把 QQ 消息接入 DSH agent，实现 AI 自动回复 QQ 消息

---

## 0. TL;DR（结论速览）

1. **DSH 桌面端默认不加载 agent-presets 插件**：需要在 cordis.patch.yml 里手动添加 `@deepseek-ai/dsh-agent-presets`，否则 session.create 传的 agentPreset 会被忽略，AI 没有 persona 也没有 MCP 工具。
2. **DSH 桌面端端口默认是 3000**（不是文档里的 3080）：需要改 `htoe-runtime.json` 里的 `"port": 3000` → `"port": 3080`。
3. **host.describe 返回的 home 字段是必填的**：DSH 桌面端返回的 host.describe 没有 home 字段，需要把 SDK schema 里的 `home: z.string()` 改为 `home: z.string().optional()`。
4. **NapCat 的 WebSocket 和 HTTP API 可能用不同端口和不同 token**：不能假设 wsUrl 和 httpUrl 用同一个端口/token，需要分别确认。
5. **start.bat 的 UTF-8 BOM 问题**：start.bat 文件头有 BOM 标记，导致 `锘緻echo` 错误，不影响功能但日志不好看。

## 1. 安装步骤

### 1.1 克隆仓库

```bash
git -c http.sslVerify=false clone https://github.com/Derpyu520/qq-bridge.git --depth 1
cd qq-bridge
npm install    # postinstall 自动修补 旧版网关 SDK 的 ESM bug
```

### 1.2 DSH 端安装

```bash
node scripts/setup-dsh.mjs
```

脚本会：
- 安装 agent preset（qq-chat，2026-09-24 起由 default 合并而来）到 `~/.dsh/.agent-presets/`
- 在 `~/.dsh/profiles/web/cordis.patch.yml` 挂载 3 个 MCP server
- 注册 qq-mode-console 插件

### 1.3 手动补充 cordis.patch.yml（关键！）

DSH 桌面端**默认不加载 agent-presets 插件**，需要手动添加：

```yaml
- insert:
    - id: agent-presets
      name: '@deepseek-ai/dsh-agent-presets'
      config:
        default: standard
        includeUserRoot: true
```

## 2. 遇到的问题与解决方案

### 2.1 NapCat WebSocket 连接失败（code=1006）

**现象**：桥接启动后报 `NapCat 错误: {}`，连接断开

**原因**：NapCat 的 WebSocket 和 HTTP API 用了不同的 token

**解决**：在 config.json 里分别配置：
```json
{
  "napcat": {
    "wsUrl": "ws://127.0.0.1:3001",      // WebSocket 端口
    "httpUrl": "http://127.0.0.1:3030",   // HTTP API 端口
    "accessToken": "http-api-token",       // HTTP API token
    "wsAccessToken": "ws-token"            // WebSocket token（如果不同）
  }
}
```

需要修改 bridge.js 第 8021 行，支持 wsAccessToken：
```javascript
// 原始：
accessToken: cfg.napcat.accessToken || undefined,
// 改为：
accessToken: cfg.napcat.wsAccessToken || cfg.napcat.accessToken || undefined,
```

### 2.2 NapCat HTTP API 端口被占用

**现象**：NapCat WebUI 保存配置时报 `EADDRINUSE: address already in use 127.0.0.1:3000`

**原因**：端口 3000 被 DeepSeek Harness.exe 占用

**解决**：在 NapCat WebUI 里把 HTTP API 端口改为其他端口（如 3030）

### 2.3 DSH 不可用，消息入队

**现象**：桥接日志刷 `连接 DSH 事件流…`，消息被入队

**原因**：config.json 里 dsh.baseUrl 端口不对

**排查方法**：
```bash
# 检查 DSH 实际运行端口
netstat -ano | grep LISTEN | grep ":(30[0-9][0-9]) "
```

**解决**：确认 DSH 实际端口，更新 config.json 的 dsh.baseUrl

### 2.4 host.describe 校验失败（home 字段缺失）

**现象**：DSH 已就绪但 checkDsh 失败，桥接判定 DSH 不可用

**原因**：DSH 桌面端的 host.describe 返回缺少 `home` 字段，SDK schema 要求它是必填的

**解决**：修改 SDK schema：
```javascript
// 文件：node_modules/@deepseek-ai/dsh-host-apiproxy/lib/types/api/host.schema.js
// 原始：
home: z.string(),
// 改为：
home: z.string().optional(),
```

### 2.5 AI 没有 QQ 工具（agentPreset 不生效）

**现象**：桥接正常，AI 回复了但说"没有 QQ Bridge 相关的工具"

**原因**：DSH 桌面端的 `agentPresets.list` 和 `agentPresets.resolve` 返回 "not found"，说明 agent-presets 服务根本没有注册

**根因**：DSH 桌面端的 base bundle（`@deepseek-ai/dsh-base/cordis.patch.yml`）里没有 `agent-presets` 条目，profile-boot 代码检测 `rows.has("agent-presets")` 为 false，直接跳过

**解决**：在 `~/.dsh/profiles/web/cordis.patch.yml` 里手动添加：
```yaml
- insert:
    - id: agent-presets
      name: '@deepseek-ai/dsh-agent-presets'
      config:
        default: standard
        includeUserRoot: true
```

### 2.6 控制台令牌太短

**现象**：打开控制台弹出令牌输入框，config.json 里配的 token 不生效

**原因**：桥接要求 consoleToken 长度 16-128 位，`061228` 只有 6 位被判定无效

**解决**：改成至少 16 位的字符串，如 `061228-bridge-console`

### 2.7 DSH 端口不是文档说的 3080

**现象**：config.json 默认写 3080，但 DSH 实际运行在 3000

**原因**：DSH 桌面端的 `htoe-runtime.json` 里配置为 3000

**解决**：改 `htoe-runtime.json` 的 `"port": 3000` → `"port": 3080`

## 3. 关键文件清单

| 文件 | 用途 |
|------|------|
| `qq-bridge/config.json` | 桥接主配置（端口/token/白名单） |
| `~/.dsh/profiles/web/cordis.patch.yml` | MCP 服务 + agent-presets 挂载 |
| `~/.dsh/.agent-presets/qq-chat/` | QQ 聊天角色 preset（2026-09-24 由 `default` 合并改名） |
| `node_modules/@deepseek-ai/dsh-host-apiproxy/lib/types/api/host.schema.js` | host.describe schema 修复 |
| `qq-bridge/src/bridge.js` (line 8021) | wsAccessToken 支持 |
| `%LOCALAPPDATA%/Programs/DeepSeek Harness/resources/backend/htoe-runtime.json` | DSH 端口配置 |

---

## 4. 启动顺序

1. DSH 桌面端（端口 3080）
2. NapCat（双击 launcher.bat）
3. 桥接（双击 start.bat）

## 5. 注意事项

- NapCat 的 WebSocket 和 HTTP API 的 token 可能不同，要分别配置
- 桥接只能运行一个实例（单实例锁）
- 修改 cordis.patch.yml 后需要重启 DSH
- DSH 升级后 SDK schema 补丁可能被覆盖，需要重新打
- start.bat 有 UTF-8 BOM 导致的 `锘緻echo` 错误，不影响功能
