# characters 角色库说明（文本架构）

每个角色 = `characters/<角色slug>/` 一个文件夹。文件夹名(slug)用作标识,建议英文/拼音,例如 `atri`、`whale`、`chiyu`。

出厂就带 **21 个角色包 + 1 张散装卡**,一共 211 份文件。改这个目录之前先看完这一页。

## 目录架构

```
characters/
├── 角色库说明.md                     ← 本文件
├── ATRI_MAIN_PROMPT.md               ← 散装卡:库根下单独一张卡(列出时标 (loose file))
├── arihara-nanami/                   ← 一个角色包 = 一个子目录
│   ├── SKILL.md                      ← ★默认档:演这个角色先读它(口吻/习惯/关系/能做不能做)
│   ├── manifest.json                 ← 元数据(name/fullName/game/cv/description),只当索引
│   ├── ULTIMATE_ROLEPLAY_PROMPT.md   ← 完整人设正文(最长的一份)
│   ├── profile.md                    ← 基础档案(姓名/身份/生日/口头禅)
│   ├── personality.md                ← 性格
│   ├── interaction.md                ← 互动方式(对主人/群友/冷场)
│   ├── memory.md                     ← 记忆要点
│   ├── relations.md                  ← 关系网
│   ├── conflicts.md                  ← 冲突/雷点
│   └── sources/wiki.md               ← 出处考据(包内一层子目录)
├── asatake-yoshino/ … yuuki-noa/     ← 其余 20 个角色包,结构同上
└── nikaidou-shinku/                  ← 空包(只留了 sources/ 占位),列得出但里面没有可读文件
```

22 个包分别是:`arihara-nanami`、`asatake-yoshino`、`atri`、`ayachi-nene`、`hitachi-mako`、`inaba-meguru`、`kariya-wakan`、`kousaka-haruka`、`kujo-miyako`、`kurama-koharu`、`maniwa-ashika`、`mibu-chisaki`、`musame`、`niimi-sora`、`nijouin-haduki`、`nikaidou-shinku`、`rena-liechtenauer`、`sanji-ayase`、`shiiba-tsumugi`、`shikibe-mayu`、`togakashi-toko`、`yuuki-noa`。

包里不保证 10 份都齐:`atri` 就没有 `sources/wiki.md`(它的考据目录是空的),多带了一份 `ULTIMATE_ROLEPLAY_PROMPT_v3.0.md`。

## 只有一张卡会进提示词

- 角色库里**只有被导入进 `persona.md` 的那一张**会作为 `[PERSONA]` 整段注入提示词。
- 其余包**根本不进提示词**。模型平时不知道库里还有什么,靠 `qq_character_list`(列包)、`qq_character_read`(读包里一份)、`qq_character_pack`(一次拼回核心几份)、`qq_character_search`(关键词搜片段)这四个**只读**工具按需去读。
- 所以"换个角色玩"是模型现场读包,不是重启就自动换人;这四个工具只读 `.md`/`.txt`/`.json`,不写任何人设文件。

## 导入规则

- GUI「人设与发言规则 → 角色库导入」扫描该目录,点角色即把内容载入人设编辑器,再点「保存人设」写入 persona.md。
- 拼 persona 时的顺序:先 `ULTIMATE_ROLEPLAY_PROMPT.md`(没有才退到 `<SLUG>_MAIN_PROMPT.md` / `ATRI_MAIN_PROMPT.md` / `main_prompt.md`),再按 `SKILL.md` → `profile.md` → `personality.md` → `interaction.md` → `memory.md` → `relations.md` → `speech.md` → `conflicts.md` 追加。
- 导入框只列**子目录**(散装卡不列),散装卡是给上面那四个工具用的。
- 默认扫描路径:桥目录/`characters`(就是这一份)、桌面 `characters`、下载目录 `characters/characters`;导入框可手动输入任意目录,`config.json` 的 `social.charactersDir` 也能指到别处。

## 如何添加自己的角色包

1. 在 `characters/` 下新建一个子目录,**一个子目录 = 一个包**,目录名就是这个角色的 slug(如 `mygirl`);
2. 默认档优先放 `SKILL.md`——工具不传 `file` 时读的就是它,没有才依次回落 `manifest.json` → `ULTIMATE_ROLEPLAY_PROMPT.md` → `personality.md`;
3. 其余维度 .md(profile / personality / interaction / relations / memory / conflicts)按需加,可以一个都没有;
4. 长文/考据建一层子目录放(如 `sources/`),**包内最多再往下两层**;
5. 只有 `.md` / `.txt` / `.json` 会被读到,单文件超 2MB 直接不读;想让角色进提示词,还得在 GUI 里导入并「保存人设」。

## 出厂形态

这一份角色库随安装包一起分发(payload 里的 `qq-bridge/characters/`),不再是只有模板的空架子;想自己加包就直接往这个目录里放。
